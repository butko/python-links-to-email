# Процесс разработки скрипта для мониторинга новых ссылок и email-уведомлений

## Введение

Задача возникла из практической необходимости: отслеживать появление новых материалов на нескольких веб-ресурсах (как обычных сайтов, так и сообществ в социальной сети ВКонтакте) и оперативно получать уведомления о них по электронной почте. Ручной обход источников отнимает время и не гарантирует своевременного обнаружения публикаций, поэтому было решено автоматизировать процесс.

В статье последовательно описаны этапы разработки, принятые технические решения и причины, по которым они были приняты. Особое внимание уделено итеративному характеру работы: многие доработки появлялись как реакция на конкретные проблемы, обнаруженные при эксплуатации.

---

## Этап 1. Постановка базовой задачи

На начальном этапе были сформулированы требования:

1. Считывать из конфигурационного файла URL страницы и адрес электронной почты.
2. Загружать страницу, собирать все ссылки из тегов `<a>`.
3. Сравнивать с сохранённым списком и находить новые.
4. Записывать новые ссылки в локальный файл.
5. Отправлять каждую новую ссылку отдельным письмом.

В качестве инструментов были выбраны:

- **Python 3** — язык с богатой экосистемой библиотек.
- **requests** — для HTTP-запросов.
- **BeautifulSoup** — для парсинга HTML.
- **smtplib** и **email.mime** — для отправки писем через SMTP.
- **configparser** — для чтения конфигурации.

Первая версия скрипта решала задачу минимально: один URL, один получатель, простой список ссылок в файле.

---

## Этап 2. Отправка почты: переход на внешний SMTP

Первый запуск выявил проблему: скрипт пытался использовать локальный SMTP-сервер (`localhost:25`), которого на машине не было, что приводило к ошибке `Connection refused`.

**Решение:** перейти на внешние SMTP-серверы (Яндекс, Gmail, Mail.ru) с обязательной аутентификацией. В конфиг были добавлены параметры `SMTP_SERVER`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`.

Дополнительно выяснилось, что крупные почтовые провайдеры не принимают обычный пароль для сторонних приложений — требуется **пароль приложения**, создаваемый в настройках безопасности аккаунта. Это стандартная практика, направленная на снижение рисков при компрометации учётных данных.

---

## Этап 3. Формирование темы письма

Изначально тема была статичной. Для информативности было решено извлекать в тему письма заголовок страницы из тега `<title>`. Так получатель мог понять содержание ссылки, не открывая её.

Для страниц, где заголовок получить не удалось, использовалось fallback-значение — сама ссылка.

---

## Этап 4. HTML-письма с кликабельными ссылками

Текстовые письма неудобны: ссылки в них не кликабельны. Было принято решение формировать письма в формате `text/html`, оборачивая ссылку в тег `<a href="...">`. Для этого использовался `MIMEText(..., "html", "utf-8")` в составе `MIMEMultipart("alternative")`.

При формировании HTML применялось экранирование специальных символов (`&`, `<`, `>`, `"`), чтобы исключить повреждение разметки и потенциальные XSS-риски на стороне почтового клиента.

---

## Этап 5. Поддержка нескольких источников

По мере расширения задач выяснилось, что одного URL недостаточно. Требовалось отслеживать несколько страниц одновременно.

**Решение:** переход от плоского конфига к формату **INI** с секциями. Каждый источник получил собственную секцию `[sourceN]` с параметром `url`. Секция `[smtp]` стала служебной.

Это дало возможность независимо настраивать каждый источник, а также упростило расширение — добавление нового источника сводится к одной секции.

---

## Этап 6. Фильтрация ссылок регулярными выражениями

При эксплуатации возникла другая проблема: с крупных сайтов собиралось слишком много ссылок, большинство из которых не представляло интереса (меню, служебные ссылки, реклама).

**Решение:** ввести фильтры на основе регулярных выражений. Параметр `filters` в секции источника содержит список шаблонов, разделённых запятыми. Ссылка проходит фильтр, если соответствует **хотя бы одному** из них.

Если `filters` не задан, применяется поведение «по умолчанию» — принимаются все ссылки. Это сохраняет обратную совместимость и упрощает конфигурацию для простых случаев.

Выбор регулярных выражений (а не простого поиска подстрок) обусловлен необходимостью поддержки сложных паттернов: числовых идентификаторов, дат, альтернатив через `|`.

---

## Этап 7. Интеграция с ВКонтакте: переход на API

Попытка применить HTML-парсинг к страницам ВКонтакте выявила принципиальное ограничение: контент сообществ загружается динамически с помощью JavaScript, а большая часть данных доступна только авторизованным пользователям. В результате `requests` и BeautifulSoup получали практически пустую страницу.

**Решение:** использовать официальный **VK API**, в частности метод `wall.get`, возвращающий список постов в структурированном JSON-формате.

Ключевые технические решения:

1. **Определение типа источника** по домену URL. Если домен входит в список `vk.com`, `vk.ru`, `vkvideo.ru`, `vk.cc`, `m.vk.com` — используется API, иначе — HTML-парсинг. Дополнительно реализована возможность явно указать тип через параметр `type`.
2. **Общий токен** хранится в секции `[vk]` и применяется ко всем VK-источникам, у которых не задан собственный токен.
3. **Получение ID сообщества** через метод `groups.getById`. Это позволило фильтровать посты, оставляя только принадлежащие самому сообществу, и отсекать репосты чужих записей.

---

## Этап 8. Формирование ссылок на посты ВКонтакте

Первоначально алгоритм извлекал ссылки из текста постов и вложений. Однако у сообществ часто публикуются посты без внешних ссылок — только текст, изображения или видео. В результате большинство публикаций не попадало в выборку.

**Решение:** для каждого поста генерировать ссылку вида `https://vk.com/wall{owner_id}_{id}` на основе полей `owner_id` и `id` из ответа API. Это гарантирует, что ни одна новая публикация не будет пропущена, независимо от её содержимого.

Дополнительно ссылки, извлечённые из текста и вложений, фильтруются по `group_id`, чтобы исключить попадание ссылок на другие сообщества.

---

## Этап 9. Обработка разметки ВКонтакте в URL

При анализе содержимого `links.txt` было замечено, что некоторые ссылки содержат посторонние суффиксы, например `https://vk.com/wall-123_456|Название`. Причина — специфическая разметка ВКонтакте `[url|text]`, в которой регулярное выражение `https?://\S+` захватывало всё до первого пробела, включая подпись.

**Решение:** изменить регулярное выражение на `https?://[^\s|\[\]]+`, останавливающееся на пробеле, вертикальной черте и квадратных скобках. Это исключило попадание служебных символов в URL.

---

## Этап 10. Порядок хранения ссылок

Изначально новые ссылки добавлялись в конец файла. При визуальном просмотре это было неудобно: свежие записи оказывались внизу, а старые — вверху.

**Решение:** изменить функцию записи так, чтобы новые ссылки добавлялись в начало файла, а существующее содержимое сохранялось ниже.

Позднее, при добавлении временных отметок, эта логика была расширена: теперь над каждой группой новых ссылок размещается отметка времени в формате `ГГГГ-ММ-ДД ЧЧ:ММ`, а группы разделяются пустой строкой. Отметка ставится **один раз на всю группу**, а не на каждую ссылку, что снижает визуальный шум.

При чтении файла строки, не начинающиеся с `http`, игнорируются — это позволяет хранить в файле служебную информацию, не нарушая логику сравнения.

---

## Этап 11. Формирование содержательной темы письма для ВКонтакте

Для обычных сайтов тема бралась из `<title>`, но у страниц ВКонтакте этот заголовок практически всегда одинаков (`ВКонтакте | ВКонтакте`), что делало уведомления неинформативными.

**Решение:** для VK-постов извлекать текст через метод `wall.getById` и использовать его в качестве темы письма (с ограничением в 200 символов).

Позднее эта логика была расширена: если у поста нет собственного текста, используется текст репоста (`copy_history`); если и его нет — формируется краткая сводка вложений (`Фото: 3, Видео: 1`).

---

## Этап 12. Полное описание содержимого поста

Темы письма оказалось недостаточно: пользователю важно видеть, что именно содержится в посте. Была реализована функция `get_vk_post_details`, возвращающая структурированное описание:

- основной текст поста,
- тексты репостов,
- список фотографий (с координатами размеров),
- названия видео и документов,
- ссылки во вложениях,
- прочие типы вложений.

В тело письма это добавлялось в виде аккуратно оформленного блока с заголовками и списками.

---

## Этап 13. Встраивание изображений

Следующим шагом стало встраивание изображений прямо в тело письма. Причины:

1. Удобство восприятия — получатель сразу видит картинку, не переходя по ссылкам.
2. Сохранение контекста — ссылки со временем могут стать недоступны.

Однако встраивание изображений увеличивает размер письма и занимает место в почтовом ящике. Поэтому были введены ограничения:

- **Целевая ширина** фотографии (`PHOTO_TARGET_WIDTH`, по умолчанию 600 px). VK возвращает изображение в нескольких размерах; выбирается ближайший к целевой ширине, но не более чем в 1.5 раза шире. Это существенно снижает вес по сравнению с максимальным размером.
- **Максимальное количество** фотографий в одном письме (`PHOTO_MAX_COUNT`, по умолчанию 10).
- **Максимальный размер** одного файла (`PHOTO_MAX_KB`, по умолчанию 500 КБ).

Изображения встраиваются через `Content-ID` (`MIMEMultipart("related")`), что позволяет ссылаться на них из HTML-разметки как `<img src="cid:...">`. Вложения при этом не сохраняются на диск — всё держится в оперативной памяти и освобождается после отправки.

---

## Этап 14. Обработка специальных символов в URL

При добавлении URL с query-параметрами (например, `?page=2%2C1`) скрипт завершался с ошибкой `InterpolationSyntaxError`. Причина — `configparser` по умолчанию использует символ `%` для подстановок.

**Решение:** при создании парсера отключить интерполяцию через `ConfigParser(interpolation=None)`. Это устранило необходимость экранировать `%` как `%%` и сделало конфиг более естественным для пользователя.

---

## Этап 15. Метка источника в теме письма

При работе с несколькими источниками стало сложно с одного взгляда понять, с какого сайта или сообщества пришло уведомление. Была добавлена метка источника:

- для обычных сайтов — домен без `www.` (например, `example.com`),
- для ВКонтакте — домен и идентификатор группы в формате `club{group_id}` (например, `vk.ru/club123456`).

Формат темы: `Новая ссылка ({метка}): {заголовок или текст}`.

Для реализации использовался вспомогательный словарь `link_sources`, сопоставляющий каждую найденную ссылку её источнику.

---

## Итоговая архитектура

В окончательном виде скрипт состоит из следующих модулей:

1. **Чтение конфигурации** (`read_config`) — поддерживает секции SMTP, VK и произвольное число источников.
2. **Сбор ссылок** — две ветки: HTML-парсинг (`fetch_links_from_page`) и VK API (`fetch_links_from_vk_api`).
3. **Фильтрация** (`filter_links`) — регулярные выражения, настраиваемые для каждого источника.
4. **Извлечение деталей поста ВКонтакте** (`get_vk_post_details`) — с поддержкой репостов и вложений.
5. **Скачивание и подготовка вложений** (`download_photos`, `_pick_photo_size`).
6. **Работа с локальным хранилищем ссылок** (`read_existing_links`, `write_new_links`) — с поддержкой временных отметок и порядком «новые сверху».
7. **Отправка писем** (`send_email`) — HTML с возможностью встраивания изображений.

Конфигурация вынесена в отдельный INI-файл, что позволяет менять поведение скрипта без правки кода. Секретные данные (токены, пароли) не хранятся в репозитории.

## Выводы

В ходе итеративной разработки скрипт прошёл путь от минимального прототипа до инструмента с развитой логикой:

- поддержка разнородных источников (статические сайты и API социальной сети),
- гибкая фильтрация,
- структурированное представление контента,
- управление вложениями с учётом ограничений почтовых сервисов,
- удобное ведение журнала обработанных ссылок.

Многие решения были приняты не на этапе проектирования, а в процессе эксплуатации — при столкновении с конкретными ограничениями (динамическая загрузка страниц, требования почтовых провайдеров, особенности разметки ВКонтакте). Это подчёркивает ценность итеративного подхода при разработке прикладных инструментов.
